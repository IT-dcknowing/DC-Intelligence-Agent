--------------------------------------------------------------------------------
- Frontend : React + TypeScript + Vite 6, Tailwind, react-markdown + remark-gfm,
  Lucide icons. Entree : src/main.tsx (StrictMode, #root, index.css).
- Backend : 1 seule Cloud Function Express `whatsappWebhook` (us-central1,
  Node 22, ~80 Ko) : functions/index.js (~2850 lignes). Toutes les routes
  /api/** et /webhook y sont reecrites (firebase.json).

  partout (allow read,write: if false) — le front n'ecrit JAMAIS directement,
  tout passe par /api (Admin SDK cote serveur).

  cote serveur, jamais exposee). Fallbacks : cles locales (Parametres) puis
  appels directs Anthropic / DeepSeek / OpenRouter.
- Modele par defaut du cabinet : inclusionai/ling-3.0-flash-vl:free
  ("Ling 3.0 Flash VL", vision + texte, gratuit, actif sans configuration).
- Prod : https://dcintelligenceio.web.app (hosting) + functions us-central1.
- Principe transversal : RIEN N'EST SIMULE. Pas de succes mensonger, pas de
  sources RAG inventees, pas d'ecriture marquee EXECUTED sans reponse reelle
  d'un connecteur. Echec explicite + toast.

A. Heuristique routeUserRequest (fallback et base), texte en minuscules,

      procedure, article N, sanction, penalite, obligation, declaration,
      echeance, code du travail) -> JURIDIQUE_FISCAL/agent-3, 0.93.
   4. Sigles fiscaux (imf, ifu, rccm) -> JURIDIQUE_FISCAL/agent-3, 0.85.
   5. Juridique general (legal flow, contentieux, conformite, fiscal, dgi,
      impot, statuts, contrat, bail, das, cnps, patente, airsi, retenue,
      teledeclaration, e-impots, juridique) -> agent-3, 0.9.
   6. Rapprochement (rapprochement, releve, banque, ecobank, sgbci, bicici,
      pointage, solde, 521, ecart) -> RAPPROCHEMENT/agent-2, 0.9.
   7. Comptabilite STRICTE (compta, facture, ecriture, syscohada, ht, ttc,
      601, 401, 411, achat, journal, imputation, bilan, balance, grand livre ;
      tva/vente/ttc generiques RETIRES car trop ambigus) ->
      COMPTABILITE/agent-1, 0.9.

      exoneration) SANS (ecriture, imputation, journal, 601, 401) ->

      Souhaitez-vous traiter une facture (Comptabilite), effectuer un

10. VALIDATEUR COMPTABLE (accountingValidator.ts:19, 7 controles)
--------------------------------------------------------------------------------
- validateAccountingProposal(proposal) -> ValidationResult {ok,
  checksPassed, totalChecks=7, erreurs[], alertes[], corrections[]}.
  1. Format JSON/ecriture bien formee (tableau non vide).
  2. Comptes SYSCOHADA existants (verifierCompteSyscohada, strict :
     regex ^[1-8][0-9]{1,7}$, match exact sinon racine 3 puis 2 chiffres).
  3. Equilibre D = C, TOLERANCE 0 (sommes arrondies au centime).
  4. Coherence TVA : si HT>0 et TVA>0, ratio = TVA/HT doit etre ~18 %
     (marge 0.02) ou ~9 %, sinon alerte TAUX ANORMAL ; sans TVA = exonere OK.
  5. Seuil immobilisation 50 000 FCFA : ligne 6056/6058 > 50 000 -> alerte +
     suggestion Classe 2.
  6. Gerant majoritaire : beneficiaire gerant + compte 6611 -> CORRECTION
     AUTOMATIQUE vers 6622 "Remuneration du gerant majoritaire" (mutation
     directe + trace dans corrections).
  7. Mentions legales facture : RCCM ou CC ou NCC + date + reference + tiers
     manquants -> alerte.
- Controles etendus (sans casser les 7) : PROFORMA BLOQUEE (ref ^P\d ou type
  PROFORMA, erreur bloquante), MONTANT INVALIDE (HT/TTC <= 0),
  normalisation comptes 6 chiffres PPP000 + alerte COMPTE TIERS MANQUANT
  (collectif 401/411 sans tiersCode/tiers), JOURNAL INCONNU + incoherence
  type (ACHAT->ACH/OD, VENTE->VEN/OD), ecritures suspectes (R1 : interdit de
  debiter un 6xx en BQ/CSE ; R2 equilibre ; R3 comptes inconnus ;
  R4 non-compensation debit+credit sur meme ligne).
- ok = aucune erreur (les alertes n'empchent pas ok=true).

13. SKILLS ET CONNAISSANCES LUS PAR LES AGENTS (RAG)

Comment les agents "lisent" les skills (3 couches) :
a) PROMPTS STATIQUES : les instructions de l'Agent Comptabilite embarquent le

   detaillee (texte >= 3 car.), searchKnowledge(texte, 2) quel que soit
   l'agent. Resultats injectes dans le prompt : "Sources documentaires
   indexees (cite-les avec [doc:titre] quand tu t'en sers) : [doc:titre]

   sans backend, reponse SANS sources, jamais inventees.

   indexed/partial existe) : le prompt recoit "base interne indexee
   disponible, ne dis jamais 'plan non accessible'" au lieu de l'avertissement

   aux prompts, pas charges tels quels au runtime) : SKILL.md (1478 lignes,

   DOSSIER_TRANSMISSION_MCP.md.

    doublon.

    uploading:true -> la miniature s'affiche INSTANTANEMENT (message-enter).
 4. userMsg {id msg-<ts>, sender user, senderName Vous, content trimmed,
    attachments?}.

 6. Miniature compressee canvas 320px jpeg 0.72 (non bloquante, images).
 7. INSERTION OPTIMISTE : titre auto (32 car. si "Nouvelle session..."),
    rename distant, uploadPromise exposee (uploadChatAttachment en fond ->
    patch storagePath puis append AVEC attachments ; echec -> patch
    uploadError + append SANS pj + toast warning ; sans fichier -> append
    simple). setChatSessions push (lastMessage = texte ou libelle generique,
    updatedAtMs), setIsGenerating(true).

    heuristique (fond).
10. Decision LLM Accueil (prompt delegation, reasoning Low, timeout 8 s) ;
    mapping vers agent-1/agent-3/agent-2/agent-router ; echec -> heuristique.
11. needsDelegation (confiance >= 0.7, agent != entree, pas de clarification).
12. createTask RUNNING (agent cible ou facade, allowedActions[0] ou PREPARE).
13. Snapshot historique (avant le nouveau message, max 8 injectes).
14. Garde-fou modele (toast + rollback du userMsg si aucun modele).
15. facilitatingAgent (cible si delegation sinon facade). RAG SYSTEMATIQUE
    (texte >= 3 car.) -> ragBlock + ragTitles (fail-soft).
16. Contexte entreprise : WITH_INTERNAL_PLAN si GENERAL_ONLY + kbIndexed
    (sinon ancien comportement comptable).
17. BRIEF LLM (§2.1, callBackendBrief : 1-2 phrases, temperature 0.5, 150
    tokens max, timeout 8 s) : accuse reception, reformule, annonce le
    routage vers le specialiste (ou pose la question de clarification, ou
    repond directement). senderName "DC Intelligence" + taskRef + append
    distant + activeAgentId = entree. Echec -> RIEN (dots), jamais de statique.
    Sans delegation, le brief EST la reponse (return).
18. Upload attendu (borne 15 s) -> imagePaths (storagePath) pour le LLM vision ;
    au-dela : sans image + mention "non lisible" (confiance < 60 % ->
    consigne de demander un renvoi, sans bloquer).

    tache, RAG/sources, contexte, stockage PJ) + interdiction formelle de
    dire « j'ai verifie/consulte/son retour » si la liste ne contient pas la
    verification.
20. DETAILLEE EN STREAMING (§1.3) : bulle vide creee (senderName = specialiste,
    streaming:true, activeAgentId = cible), generateChatResponse(stream:true,
    onToken, signal, images, hasImages, firstTokenTimeoutMs 20 s) ; tokens
    appendus au fil de l'eau + curseur ; finalize a la fin (ou pose d'un bloc
    en repli direct). Proposition JSON extraite APRES le stream complet ->
    PropositionEcriture -> validateAccountingProposal -> logAuditInteraction
    (question [visible=X specialist=Y task=Z], sourcesRag reelles) ; la bulle
    existante est completee (proposal/validation, PAS de doublon) + append
    distant (agentName = specialiste).
21. Erreurs (§3.3 + §5, JAMAIS de silence) : log structure
    {timestamp, agent, tool:chat/chat_detail, error_code, user_id, message_id}
    (console, sans secrets) ; bulle vide supprimee ; message agent :
    timeout 20 s -> "Le traitement prend plus de temps que prevu.
    Voulez-vous reessayer ou contacter un agent humain ?" ; brief KO ->
    "Je n'arrive pas a vous repondre..." ; autre echec delegue -> l'Accueil
    reprend : "Je n'ai pas pu traiter votre demande. Voulez-vous reessayer
    ou parler a un humain ? (detail)" ; sinon texte friendly. + toast error.
22. finally setIsGenerating(false). Dots discrets tant que le stream n'a pas
